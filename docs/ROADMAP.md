# Vereinbarter Umfang

CK3 ist das Hauptspiel. Minecraft läuft gleichzeitig. Situationsbedingter Wechsel automatisch; freies Wechseln und Reisen zusätzlich. Einzelspieler hat Priorität, Multiplayer mit getrennten Reichen bleibt optional.

| Teil | Erste Umsetzung | Weiteres Ziel / erforderlicher Nachweis |
| --- | --- | --- |
| Reise | CK3-Reisestart, echte Charakter-/Provinzdaten, isolierter Minecraft-Weg | Routenabschnitte aus tatsächlichen CK3-Reiseplänen; kein erfundener Weltkartenimport |
| Duell | Tatsächlicher Hofcharakter, Kampfgeschick beeinflusst Gegner, Sieg/Niederlage/Abbruch | Weitere Duellarten und geprüfte Rückwirkungen; CK3-Modelle nur aus eigener Installation |
| Freier Wechsel | CK3-Entscheidung für eine freie Reiseszene, Rückkehrbefehl | Jederzeitiger Wechsel mit passendem Kampagnenzustand |
| Ereignisse | Ein eigener Wegduell-Ereignistyp | Einzelne passende CK3-Ereignisse gezielt integrieren, keine pauschale Übernahme aller Vanilla-Ereignisse |
| Belagerung | Noch nicht implementiert | Eine echte laufende CK3-Belagerung erkennen, spielen und kontrolliert beeinflussen |
| Schlacht | Noch nicht implementiert | CK3-Krieg, Armeen und Kommandanten übertragen; ein überprüfbares Schlachtergebnis zurückgeben |
| Automatischer Wechsel | Minecraft nimmt Warteschlangenereignisse automatisch an, wenn die private Instanz bereits läuft | CK3 pausieren, Prozesswechsel, sichere Rückgabe und Bestätigung auf Windows tatsächlich testen |
| Multiplayer | Noch nicht implementiert; andere Instanzen können eine Solo-Sitzung nicht übernehmen | Gemeinsame Zeit, getrennte Reiche, Relay/Lobby und Host/Join mit zwei echten Kopien testen; erst danach Melty-Multiplayer-Rezept |
| Veröffentlichung | Lokaler Entwicklungsstand | Gepackte Laufzeiten und Prism, bestätigtes Ein-Klick-Rezept, echter Spieltest und Gameplay-Bild, Freigabe |

Die aktiven Tabellen enthalten ausschließlich die Systeme der ersten Umsetzung. Noch nicht implementierte Systeme stehen hier, nicht als scheinbar fertige Tabellenzeilen. Bei Erweiterung wird das entsprechende System zuerst in einer eigenen Tabelle beschrieben, einschließlich seiner Bezüge, und erst dann implementiert.
